# 10/28 Wed

## DirectXShaderCompiler をビルド

https://github.com/microsoft/DirectXShaderCompiler/blob/main/docs/BuildingAndTestingDXC.rst  
上記リンクの「Generating a Visual Studio Solution」を参照。


クローン  
`git clone https://github.com/microsoft/DirectXShaderCompiler.git`  
`git submodule update --init --recursive`

準備  
Windows SDK と Windows Driver Kit をインストールしておく。

Cmake  
プログラム一覧の中から Visual Studio 2022 以下の「Developer Command Prompt for VS 2022」を起動する。
Git から取得したフォルダに注意しつつ、下記のコマンドで cmake を実行する。

```
cmake D:/Github/DirectXShaderCompiler -B D:/Github/DirectXShaderCompiler/output -C D:/Github/DirectXShaderCompiler/cmake/caches/PredefinedParams.cmake -DCMAKE_BUILD_TYPE=Debug -G "Visual Studio 17 2022"
```

成功すれば output 以下に LLVM.sln が作成されるので VS から起動してビルドする。


## Unity での C# デバッグ

Unity で C#を使ったコーディングをするとき、太古の昔は Mono Develop を使い、Visual Studio Code がリリースされてからはそちらに移行していた。Mac 環境であれば、引き続き Visual Studio Code で良さそうだが、Windows なら Visual Studio でも開発は可能みたい。

### Visual Studio プラグイン
Visual Studio Installer から「Visual Studio Tools for Unity」をインストールする。

### Unity の設定
Preferences > External Tools に移動し、External Script Editor から「Visual Studio」を選択する。Visual Studio がインストールされていれば、デフォルトで設定されているはず。

### デバッグ実行
Visual Studio でブレークポイントを貼って実行させておく。Unity から Play すれば、ブレークポイントに入る。

## ブログの運用

### 記事データ
ブログを運用したいが、記事は全て md で作って Github で管理したい。md で管理すれば、AI にも記事を書かせられる。
md から静的なページを作って、Claudflare Pages でホスティングするようにする。

md には、独自の構文を入れたいので、C++ で独自パーサーを作成して、自宅の余っている PC で html 変換を行う。
自宅の Jenkins から Github を定期的に pooling して、更新があれば md から html を生成して、Claudeflare に自動でアップロードする。

ここで生成する html はあくまで、md から記事部分だけを変換したもの。完全なページは、サーバー側で生成する。

### ページング
Cloudflare D1（SQLite）にも記事情報を格納しておく。
/page/2/ にアクセスされたら、Cloudflare Workers が、D1 から記事情報を取得して、テンプレートを元に html を作成して、完成された html を返すようにすればページングが実現できる。

### 完成ページの配信
記事htmlを基に、サーバー側で完全なhtmlを作成する。
ここも、Workers + D1 を使って処理する。記事一覧や、最新記事のリンク情報が必要。

### 考慮すべきこと
どこまでを静的に保存して、どこまでを動的にするか、設計が必要。コストに直結する

## Visual Studio Code からの Copilot 利用
最近の Visual Studio Code には、デフォルトで GitHub Copilot のプラグインが含まれている。

そのため、Copilot のアカウントがあれば、VSCode で AI 支援が受けられる。
ちなみに、Microsoft Copilot と GitHub Copilot は別物なので注意が必要。Microsoft Copilot は Office の資料作成など、一般的なタスク向けに用意されている。
GitHub Copilot はコード生成に特化しており、使用できるモデルも OpenAI の GPT 系に加えて、Claude なども選択できる。

### ChatGPT のアカウントしかない場合
当たり前だが、Github Copilot を利用するには、Github Copilot のアカウントが必要。
ChatGPT のアカウントしかない場合は、OpenAI 公式の Codex 拡張機能を VS Code に導入して、ChatGPTアカウントでログインすれば GPT 系のモデルを使ったコード生成などが可能になる。

## Jekyll でのブログ運用
GitHub Page + Jekyll でブログを運用してみる。  

Jekyll の実行は、GitHub 標準で使えるものと、Github Actions から使うやり方があるみたいだが、今は標準のものを使っている。

GitHub Page の設定で `Build and deployment` にある Source を `Deploy from a branch` にすることで、md ファイルをアップロードするだけで自動で Jekyll が実行されるみたい。

自動実行したくない場合は、リポジトリ内に .nojekyll を配置するか、もしくは Source が `GitHub Actions` になっている場合は自動では更新されない。Github Actions を使う場合は自分でワークフローの設定が必要になる。

また、Deploy from a branch 設定だと、1時間に10回の Deploy 制限があるみたい。
